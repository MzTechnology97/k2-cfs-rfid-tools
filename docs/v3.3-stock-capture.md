# v3.3 stock-task Bambu capture

v3.3 is the first K2 CFS RFID candidate validated end-to-end with a real Bambu Lab spool.

Unlike the earlier direct diagnostic RF experiments, API7 leaves RF ownership with Creality's stock RFID manager. The host derives the Bambu Key A from the tag UID, arms a one-shot three-key override, and then asks the normal CFS driver to perform the standard force-read operation. The firmware wrapper substitutes the keys only at the original stock authentication calls and captures the successful legacy read result into scratch storage.

## Data flow

```text
K2-OpenHost / CM5
  -> read stock internal UID
  -> derive Bambu sector-1 Key A
  -> API7 ARM_KEYS3
  -> normal CFS force_rfid_read()
  -> Creality stock RFID task
  -> original auth/read calls with temporary Key A
  -> capture block 4 + block 5 RGBA into scratch
  -> CM5 reads scratch and decodes material + colour
  -> CLEAR_KEYS
```

The three stock legacy reads are for blocks 4, 5 and 6. They are all in MIFARE Classic sector 1, so the same derived sector-1 Key A is armed three times.

## Captured data

API7 intentionally captures only enough data to identify the spool preset and colour: all 16 bytes of block 4 plus the first four bytes of block 5. The CFS remains responsible for its own remaining-filament percentage. K2-OpenHost does not currently use Bambu's nominal-length block for API7 spools.

## Compatibility

The validated target is exactly `cfs0_050_G32` / `cfs0_000_153`. The current host implementation refuses the API7 stock-capture path when runtime inspection reports the secure backend because result capture has only been validated for the legacy backend.

## Result

On 2026-10-07 the reference printer successfully identified a Bambu `PLA Matte` spool with UID `233A111D` and colour `#FFFFFF`, first through a manual API7 read and then through the automatic Creality-unknown -> Bambu-fallback path.
